# 研究计划

## 题目

- 中文：面向持续任务的智能体可信经验迁移与自适应规划方法研究
- 英文：Trustworthy Experience Transfer and Adaptive Planning for LLM Agents in Continual Task Streams
- 类型：实验研究类；方向：人工智能、智能体技术

## 研究问题

基于大模型的智能体可以把过去的轨迹总结成经验，在后续任务中复用。在持续任务中，这件事会遇到三个问题：

1. **经验会过时或只在部分场景成立。** 同一条经验在 A 场景正确，到 B 场景可能是错的；环境在同一场景内部也可能悄悄变化。
2. **直接检索会把错误经验带进新任务。** 只按任务描述的相似度检索，看不出一条经验在当前场景是否还可靠，于是产生负迁移。
3. **固定计划无法应对执行中的意外。** 工具损坏、物品不在记忆中的位置时，智能体需要及时改计划，同时把"经验失效"这个信号反馈给记忆库。

## 研究内容与实现对应

### 1. 可信经验评估与记忆更新

- 每条经验记录全局证据（被使用后成功、失败、被环境直接否定的次数，独立重复归纳的次数），也按场景分别记录证据。
- 全局可信度用 Beta 后验均值；场景可信度以全局均值为先验做收缩估计。
- 每条证据（创建、重复归纳、使用后成功、失败、被环境否定）连同回合序号和场景写入经验的证据日志，可信度由日志计算。
- **时间的处理（已定）：旧证据打折，而不是直接衰减可信度。** 每条证据的权重为 γ^(距今回合数)，γ=0.99。效果是均值变化很慢，但不确定性（Beta 分布的标准差）变大。理由：一条经验很久没被验证，只说明"我们对它的把握变小了"，不说明它错了。
  - 对比做法一"可信度往 0 衰减"：把"没有证据"当成"有反面证据"，好经验长期不用会被过滤（回到旧场景时等于自己制造遗忘）。
  - 对比做法二"可信度往 0.5 回归"：丢掉了证据量的信息，被证明是错的经验放久了会自己"复活"。
  - 两种对比做法保留为 `--decay-mode to_zero / to_half`，作为对比实验。
  - 被环境否定而隔离的经验，隔离判断用不打折的证据，不会因为时间过去而自动解除。
  - 依据：非平稳环境中的折扣 Beta / 折扣 Thompson 采样（Raj & Kalyani, 2017，见 related-work.md）。
- 输出：每条检索结果同时带可信度和不确定性，供研究内容 3 决定"直接用 / 先验证 / 不用"。
- 实现：`evoplan/memory/trust.py`、`evoplan/memory/store.py`。
- 待研究：失败时收窄适用范围（利用证据日志里的场景信息）；参数敏感性（γ、先验、阈值）；信用分配（一次失败由哪条经验负责）；用大模型做反思时的经验去重与合并。

### 2. 跨任务经验迁移与负迁移抑制

- 检索排序依据 相似度 × 当前场景可信度；门控阈值过滤低相似、低可信和全局隔离的经验。
- 没见过的场景以全局可信度作先验，因此有用的经验仍然可以迁移过去。
- 实现：`ExperienceStore.retrieve`。
- 待研究：门控阈值自适应；只有文本经验时，如何定义"场景"（任务簇、环境指纹）。

### 3. 状态感知自适应规划

- 状态监控器识别三类触发：资源不可用、记忆预期与观测矛盾、连续失败无进展；暂时性失败只重试，不触发重规划。
- 重规划会更新信念，并返回被否定的经验，由记忆库在当前场景降低它们的可信度。
- 实现：`evoplan/planning/monitor.py`、`planner.py`。
- 待研究：按不确定性验证——高可信且确定直接复用，拿不准先低成本检查，低可信或连续失败则不用经验、重规划；基于大模型的触发判断；验证与重规划的 Token 成本控制。

### 4. 实验原型与评估

- 对比：无经验基线 `no_exp`、直接经验检索 `naive_retrieval`、本文方法 `evoplan`。
- 消融：去掉可信度、改用全局可信度、去掉门控、去掉重规划。
- 指标（定义见 `evoplan/metrics.py`）：任务成功率、平均步数、迁移收益（相对无经验基线的成功率差）、步数节省、负迁移率、失败恢复率、经验可靠性（注入经验中真实成立的比例）、Token 用量与 API 成本。
- 任务流：新场景切换、回到旧场景、同场景漂移三类阶段，分阶段报告指标。
- **核心实验：错误经验注入。** 把"局部正确但不可推广"的经验按 0 / 10 / 30 / 50% 混入经验库，对比无记忆、直接检索和本文方法的成功率与负迁移率（尚未实现）。
- 待补指标：可信度准确性（AUROC）、每成功一个任务的 Token、额外开销占比（总结与验证 Token / 总 Token）。

## 离线验证结果（ToyKitchen）

5 个随机种子，任务流 `A:40,B:40,A:20,A@C:40`，故障率 0.08，步数预算 14：

- 有经验的方法成功率约 0.97，无经验基线约 0.89，平均步数从 10.3 降到 7.5 左右。
- `evoplan` 与 `naive_retrieval` 差距很小；漂移阶段 `evoplan` 平均步数略少（约 7.6 对 8.1）。消融结果不稳定，有的消融版本甚至更好。
- 记忆快照显示，场景可信度符合设计预期：例如"苹果在冰箱"在 A 场景约 0.98，被 B 场景否定后，在 B 场景降到约 0.37。
- 三种时间处理方式（`evidence` / `to_half` / `to_zero`）在 ToyKitchen 上成功率都在 0.96–0.97，差异在噪声范围内。任务流只有 140 个任务，衰减的作用体现不出来；要在 ALFWorld 的长任务流和错误经验注入实验中比较。

结论：流程和各模块的行为已经验证；方法是否有效，要在正式基准上用真实大模型检验。ToyKitchen 里的物品位置这类知识太容易靠场景标签区分，区分度不够。
